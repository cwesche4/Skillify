## Auditor Walkthrough (Narrative)

1. **Request initiation control:** Attempt `POST /api/security-pack/request` as an authenticated member with and without entitlements; expect 403 when missing. Query `SecurityPackAuditEvent` to confirm `REQUEST_SUBMITTED` (and `VALIDATION_FAILED` if NDA not confirmed) is recorded without payload storage.
2. **Approval workflow:** As a reviewer role, call `GET /api/internal/security-pack/approvals`; confirm only pending, entitlement-eligible items appear. Approve or reject via `POST /api/security-pack/request/:id/decision`; verify corresponding audit events in `GET /api/security-pack/request/:id`.
3. **Audit immutability:** Inspect `SecurityPackAuditEvent` for append-only records (no updates/deletes). Confirm timeline ordering via `GET /api/security-pack/request/:id` matches creation times.
4. **Automation safeguards:** Call the delivery callback with an invalid token to observe 401/404; with a valid token, ensure a single `DELIVERY_MARKED` event is created. Replaying the callback should not create duplicates.
5. **Download protections:** Before delivery, `GET /api/security-pack/request/:id/download` returns 404. After `DELIVERY_MARKED`, the same call returns a resolved download (or redirect) only for requester/admin with entitlements. No URLs are stored in audit records.
6. **Entitlement enforcement:** For each route (request, timeline, download, artifact, audit feed, approvals), test access without required entitlements; expect 403/404 per concealment rules. Confirm enforcement logic is centralized (see `docs/security-pack/entitlement-enforcement-final.md`).
7. **Delay disclaimer:** Verify timeline API includes the footnote “Events are generated automatically and may be delayed during approval or delivery,” indicating no timing SLAs.

All evidence relies on server-side APIs and append-only audit data; no client-side assumptions or hidden state affect control verification.
